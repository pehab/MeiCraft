## Non-negotiable compatibility constraints

- Do not alter the terrain generator of existing online worlds in place. Persist a terrain generation version; legacy worlds must continue using their original baseline.
- Never regenerate an edited cell just because its current value equals its original terrain block. Check recorded edits/history and generation version.
- Preserve old online protocol 4/5 migration to protocol 6, encrypted private inventories, anonymous UID and journal/checkpoint semantics.
- Version and migrate any fixed-size inventory serialization and block-ID validation before adding IDs. Old saves must remain loadable.
- Existing glass remains block ID 8; its rendering-only change requires no world migration.
- Gameplay-changing block mutations online must use the existing atomic RTDB journal/inventory transaction path, with concurrency and retry protection. No new Firestore writes per gameplay action.
- Local-only visuals (particles, fog, water shimmer, lava flicker, smoke animation) must never produce network writes.
- Do not enable offline Nature.tick / Forge.step globally for online worlds. Any new timed online reaction needs a durable, idempotent, conflict-safe state transition, including reconnect and host change.
- Do not silently modify existing builds, inventories, worlds or player permissions.

## Implementation slices (each slice: unit tests + Android CI)

1. **Compatibility foundation**: inventory/block codec versions, stable legacy terrain baseline, new world terrain version, migration tests. Include existing-world and fresh-world fixtures; negative/invalid block ID tests.
2. **Materials and generation**: coal ore and black coal blocks; basalt; crystals; vegetation. Deterministic seed tests; no overlap with structures or player edits; chunk boundaries.
3. **Renderer**: transparent glass (opaque pass then blended transparent pass, depth test on/depth write off, face occlusion and ordering), vegetation meshes, water/lava shader animation, fog refinement.
4. **Cosmetic particles**: pooled mining debris, fire/smoke and crystal glints, camera-distance culling, no persistent/network state.
5. **Interactions**: bounded coal/lava reaction and secret recipes. Validate atomic consumption and concurrency in RTDB; offline parity without unintended global simulation.
6. **Release verification**: migration of an actual backed-up 0.8.3 online world; test 2-4 devices, concurrent edits, reconnection, host failover, checkpoint recovery, quota/latency, old saves, glass overdraw, particle budget.

## Visual performance guardrails

- Start with at most 150 simultaneously rendered cosmetic particles, culled by distance.
- Avoid rebuilding terrain meshes for every animated water/lava/fire frame.
- Use a separate transparent draw pass; test multiple overlapping panes and chunk boundaries.
- Vegetation uses crossed quads or equivalent lightweight geometry and distance culling.
- Compare p95/p99 frame times, draw calls, mesh rebuild time, memory and RTDB/Firestore usage to the rc.6 baseline; do not claim an improvement without measurements.

## Release policy

Work stays on PR #20 branch feature/1.0-contract-performance. Do not merge, publish, or deploy Firebase rules without explicit approval. CI green alone is not proof of migration safety or real-device performance.
