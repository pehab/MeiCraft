## Kontrollierter Geometrie-Benchmark (rc.2, indiziert)

Linux / OpenJDK 17; 40 Aufwärmdurchläufe, 101 alternierende Messungen je Kern und Szene.
Reiner Geometrieaufbau ohne OpenGL-Upload. Der Referenzpfad gibt seinen ursprünglichen
Builder-Puffer zurück; die nur für den exakten Vergleich benötigte kompakte Ergebniskopie
wird nicht mitgemessen. Beide Ergebnisse werden über dieselbe volatile Senke veröffentlicht.
Zeiten sind ein lokaler Lauf, kein Tablet-Nachweis; Streuung ist insbesondere bei p95 sichtbar.

| Szene | 0.8.3 p50 / p95 (ms) | Kandidat p50 / p95 (ms) |
| --- | ---: | ---: |
| Gemischte Materialien mit Ritualhitze | 1,548 / 3,410 | 0,814 / 1,149 |
| Dichte Wasser-/Lava-Grenzen | 4,495 / 6,369 | 1,464 / 1,879 |
| Gelände | 0,137 / 0,303 | 0,062 / 0,091 |
| Online-Bereichsgrenze | 0,172 / 0,570 | 0,062 / 0,076 |
| Leer | 0,041 / 0,056 | 0,020 / 0,020 |

In allen Vertragszenen stimmen nach Index-Expansion Anzahl, Reihenfolge und Float-Bits
der Vertices, UVs und Helligkeitswerte überein. Wiederholte Aufbauten gleicher Größe
ersetzen das Geometriearray nicht. Der Renderer verwendet seinen direkten Uploadpuffer
wieder. Der gemeinsame 16-Bit-Indexpuffer kostet einmalig rund 192 KiB pro Kontext;
die eigentlichen Vertex-Uploads sind bei gleicher Geometrie um ein Drittel kleiner.

Die früheren reinen Orakel-Benchmarks enthielten im Referenzpfad noch die abschließende
Ergebniskopie. Die obige Messung ersetzt diese Zahlen für den Leistungsvergleich.

## Kontrollierter Firestore-Vergleich

205 Blockdokumente mit gemeinsamem Zeitstempel; nach dem vollständigen Snapshot wird
eines verändert. Die alte inklusive Abfrage lädt auf ihrer ersten Seite erneut 200
Dokumente; der neue exklusive Snapshot-Filter liefert genau das eine später veränderte
Dokument. Beide ersten Seiten und die restlichen fünf Dokumente werden aus demselben
Snapshot gelesen. Projektion erhält die Versionsmetadaten. Banned/Outsider-Zugriffe
auf den neuen batchGet-Pfad werden verweigert.

Keine Prozentangabe für eine vollständige Spielsession: ruhende Welten sparen dadurch
keine Dokumentlesungen; batchGet und Projektionen benötigen zusätzliche Anfragebytes.
Die drei Dokument-Schreibvorgänge pro Block bleiben gleich. Gesendete Anfrageinhalte
werden deshalb zusätzlich diagnostiziert.

## Vor endgültiger Freigabe

Der Vergleich auf den tatsächlichen Tablets fehlt: Frameabstände einschließlich p99,
Aktionsbestätigung, Sichtbarkeit bei Mitspielern, kalter Start, Grenzen und Verbrauch
im gleichen Mehrgeräte-Ablauf. Die vorliegenden Ergebnisse rechtfertigen Testkandidaten,
keine endgültige 1.0-Freigabe. Der aktuelle technische CI-Stand steht im PR.
